# Gate: ビルド・検証・変更管理

## 目的

同梱コードとデータの渡し方を、再現可能なビルドと検証で確認する。

## 判定条件

- [x] `make build` と `make test` が成功する。
- [x] データや同梱コードを変更した場合、同梱データを指定した `make data-test` と `make reference-test` が成功する。公式比較には CF96・自転・月・大気・食を含める。
- [x] `DATA_ROOT` は絶対パスの `data` ディレクトリとして受け取り、コアのデータテストにはその親ディレクトリを渡す。
- [x] `DATA_ROOT` の既定値は本リポジトリ内を指し、データ不足の場合は手順を示すエラーで停止する。
- [x] クリーンなビルドは Lua ソースのダウンロードや他リポジトリを必要としない。
- [x] 作業完了時に `git status`、変更ファイル、差分量を確認し、300 行以上の変更では原則 commit する。
- [x] commit 前に `/simplifier-lai` skill の利用可否と依存関係を確認し、利用できない場合は報告する。
- [x] gate 検証用コピーに判定を記録し、実施したテストと未実施の確認を作業報告へ残す。
- [x] 追加衛星・描画品質・全画面・HTML を採用する場合、共通側の対応試験と採用 SHA を特定する。HTML helper の構成、実 OS 通知、実機・複数画面など未確認の範囲を成功扱いしない。
- [x] 単位7の採用時は、JSON v7 の正常復元・不正 ID/出典不一致/上限超過による全体拒否、小天体・衛星の表示集合、PTH 探査機、全天図・地平図の星座集合・星座絵・天の川、恒星名選択・明るさ、雲・夜景・大気、食と影・風景・時間操作・原地点IDについて共通側の試験を特定し、ラッパーからの検証結果と区別して記録する。
- [x] `VALIDATION.md` と gate の判定には実際の対象と実施結果だけを記録し、未検証の機能を検証済みと説明しない。

## 不合格条件

- [ ] 失敗した検証を成功として報告する。
- [ ] 別リポジトリの内容を、同梱せずに本リポジトリに保存されたと扱う。

## 検証記録

基点 c626ae4 の native/gui 修正に対し、最終統合状態で `make -j6 build`、`make -j6 test`、`make -j6 data-test`、`make -j6 smoke` が成功した。`make -j6 reference-test` は本単位の GUI 修正前に成功し、その後の core とデータの差分はない。CF96・自転・月・大気・食の公式比較を含む。P1-1 の形状・描画・非同期選択・実データ精度、P1-8 の Lua 注視、P1-5 の実 CAB と人工深度の地形遮蔽の専用回帰も成功した。詳細と fixture 修正履歴は VALIDATION.md に記録した。

DATA_ROOT は同梱 resources/data の絶対パスを使い、既存 Makefile の core 向け親ディレクトリへの受け渡しを維持する。データ不足の診断と同梱 Lua ソースによるビルド経路は変更しない。今回はクリーン環境を新設しての再ビルドではなく、既存 checkout でのビルド・回帰試験である。追加衛星・全画面・HTML・単位7の新規採用はなく、従来の採用元と未確認範囲を維持する。

Git 状態・対象ファイル・差分量を確認し、300 行を超える今回の変更とこの検証コピーを明示指定で commit する。新規依存はなく、既存の C++ 標準ライブラリ、AppKit/CoreGraphics を使用する。`/simplifier-lai` は利用できず、利用可能な `simplify-lai` は LobbyAI 専用のため適用しない。リポジトリ全体方針は変更しない。別チャットの Rust 移行文書・元 gate と既存の検証コピーは commit 対象から除外する。

旧 Plus 比較と手動 GUI の全距離操作は未実施。自動試験だけでは旧版の外観や未知の移動契約を確定できないため、星座への移動と Targets.select 座標指定はユーザーの判断に従い保留する。Rust 移行・3 OS の動作確認は本単位に含まない。不合格条件には該当せず、同節のチェックボックスは未選択とした。
