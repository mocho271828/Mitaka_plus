# Gate: クロスプラットフォームとRustへの移行

## 目的

現在のMac版の機能を保ちながら3 OS共通のGUI・描画へ移り, 同じ境界を使ってコアをRustへ置き換える.
計画の合格と実装段階の完了を区別する.

## 判定条件

- [x] 移行計画にA0〜A5/B0〜B6の作業・検証可能な完了条件があり, 未実施の段階を完了扱いしていない.
- [x] 現Mac版の基準commit・データ・受入機能をA0で確定し, 旧Plusの未対応機能と区別する手順がある.
- [x] Windows・Linux・macOSを初期段階から検証し, CIと実機, LinuxのX11/Wayland, 対象CPU/GPUを区別する計画になっている.
- [x] C++を一時境界に閉じ込め, 機能ごとの状態の正本とsnapshotの所有権を一つにする契約がある.
- [x] JSON v9の全体検証・停止復元, 原bytes/ID, 物理半径, 精密カメラのpc基準とAU差分を保持する条件がある.
- [x] HTMLの信頼境界, Luaの現行権限・停止, メディア実ファイルの実証をA1で行い, 必須機能の欠落を許容していない.
- [x] Bは副作用なしの比較から機能単位で切り替え, 独自C++/Objective-C++を製品の通常ビルド・実行から外す条件を持つ.
- [x] 実装を変更した場合, 対象段階・基準版・環境・試験結果を記録し, 段階の未達条件を残して完了と報告していない. 文書のみの場合は実装未着手と明記している.
- [x] 依存候補・未決事項と検証済み事実を分け, 外部C/C++依存や比較用原本の残存を「独自コアのRust化」と混同していない.

## 不合格条件

- [ ] 計画を作成しただけで移行実装・3 OS動作・Mac機能維持を検証済みと報告している.
- [ ] 現Mac版の受入機能を黙って除外する, 状態を二重管理する, または未検証の結果へ実行時fallbackして移行完了とする.
- [ ] 原本を削除する, またはB完了後も製品経路が独自C++/Objective-C++へ依存している.

## 判定

YES

## 検証記録

別チャットの移行計画と元 gate は変更しない。A0〜A5/B0〜B6、3 OS の検証区分、単一の状態と snapshot、JSON v9・精密カメラ、HTML/Lua/メディア、比較からの切替と独自 C++ の製品経路からの除去が計画に記されていることを確認した。これは移行計画との整合の判定であり、各段階の実装・受入試験の完了判定ではない。

今回の対象段階は移行 A0 より前の現 Mac 版、基点は d7bae2c。macOS 26.6.2 / arm64 で CAM-08 の4ブラウザの操作を変更し、build/test/data-test/reference-test/smoke が成功した。Rust 移行の実装は未着手であり、A0 の基準版確定も今回の完了に含めない。Windows・Linux、X11/Wayland、他の CPU/GPU の確認は未実施。既存機能を除外したり、未検証の fallback を追加したりしていない。

IMPLEMENTATION_POLICY.md、investigation/native-plus/README.md、移行計画、元 migration gate の4ファイルと既存検証コピー269ファイルは作業前 SHA-256 と一致する。これらの既存差分は今回の commit に含めず、新しく作成した本ディレクトリの検証記録だけを登録する。

不合格条件に該当しないため、同節のチェックボックスは未選択とした。
