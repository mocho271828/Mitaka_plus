# 優先順位4：小天体の軌道と探査機データ

2026-11-12。PR #8 の `3f50687` を修正前とし、Apple M4 / macOS 26.6.2 で同じ条件の実画面を比較した。使用した Plus の入力575ファイルは、一般ファイル573件が Git blob と、地球・火星地形2件が Git LFS の SHA-256 とサイズに一致する。外部の通常版や検証用に作った軌道定義は Plus の原本とは区別する。

## 太陽系画面：拡大すると天体と軌道線が離れる

PR #8 の製品オブジェクトと AppController を使う AppKit ウィンドウで、元ファイルと原行を指定して表示集合を対象1天体に絞った。天体を選択し、名前を消し、軌道線だけをオン／オフした。両フレームとも同じカメラの完成描画を待ち、ScreenCaptureKit で PID とウィンドウ番号を照合して取得。地図は964×529 pt（1,928×1,058物理画素）、画角45°、yaw 30°、pitch 85°。非同期状態の文字を含む地図の上下端を除き、RGBのいずれかの成分が12を超えて変化した画素を軌道線の観測に使った。

セレス（個別・36 byte）、イカルス（個別）、セドナ（個別・36 byte）の5出典で、それぞれ広域、天体に寄った視点（JD 2451545.0）、37.5日後に寄った視点を比較した。距離はセレス10／0.01 AU、イカルス6／0.003 AU、セドナ2,400／0.05 AU。広域は太陽中心、寄った視点は当該日時の天体中心。さらに個別3天体で元期ちょうどと、元期後最初の近日点で接近表示を追加し、修正前後それぞれ21条件×オン／オフで合計84画面を取得した。修正前は1周129標本、修正後は201標本、欠損はどちらも0。

| --- | --- | --- |
| セレス | 40.1、67.0 px | 個別と36 byteの両方で天体を通る |
| イカルス | 95.2、109.8 px | 離心率の大きい軌道でも天体を通る |

離心近点角で区切った2つの標本を直線で結ぶと、視点を近づけた際に弦が天体を通らなくなる。修正後は画面内にある楕円軌道の天体について、同じ日時の実位置を1周期の位相へ対応づける。実位置を挟む区間とその両隣の弦を調べる。実位置が弦から0.25 ptを超えて離れる場合はそこを通し、各区間の中間点が弦から0.25 pt以内になるまで同じ評価器で細分する。一周期の始点・終点をまたぐ両隣も対象とし、近クリップや極端な拡大でも各側の細分は6段まで。この補正で全軌道のキャッシュ・要求標本数・出典IDを変えず、欠損標本は結ばない。2標本では始点と1周期後が同じ点を指し、閉楕円の輪郭を表せない。極端に少ない標本数、全拡大率・軌道全周での一様な誤差は保証しない。

画面内の独立した軌跡点でも精度を調べた。1区間の両端と中間、4周期前・20周期後を含む8位相について、前後151点を独立の日時で評価し、画面内の各点と描画線分の最短距離を測った。当初の129標本で実位置を含む1区間だけを直すと、元期ちょうどのセドナで付近の軌跡が16.19 ptずれた。隣接区間も修正した中間版では3天体×8位相の最大差が0.228 pt、7 AUから見た全カタログは修正前と全画素が一致した。[129標本・元期始点での切り分け](../../verification/p4/native-orbit-phase.tsv)

旧版の仕様を確認して、楕円の始点を元期直前または元期と同時の近日点に変更し、既定を201標本（200辺）とした。保存済みの明示値は維持する。最終版の3天体×8位相の最大差は既定201標本で0.119 pt以内。元期の実日時も加えた3天体×9位相では、既定201標本で0.227 pt未満、明示した129標本で0.247 pt以内だった。実ウィンドウの接近16条件ではいずれも描画線が対象中心を通り、軌道オン／オフによる画素差は中央の物理画素でも確認できた。[最終版の54条件](../../verification/p4/native-orbit-phase-final.tsv)

[修正前後の実測と画像ハッシュ](../../verification/p4/native-orbits.tsv)。線の幾何距離と、印で隠れる部分を含む実画面で初めて画素差が見える距離を別の列に記録。撮影原本は検証Macの `local/verification/p4-native/` に保管した。

## 全カタログ表示の負荷

小惑星・TNO の軌道線を全件表示したときだけを比較した（彗星・名称なし、JD 2451545、7 AU、800×600 RGBA）。全出典19,475行のうち要求17,018行。位置未認定の37 byte 8,510行を除く8,508軌道で、既定201標本は合計1,710,108点になり、旧上限1,572,864では拒否される。対応形式の標本予算を2,097,152に変更し、依然として超過時は行を間引かず要求全体を拒否する。彗星の予算は524,288点のまま。標本数は既存UIの共通設定のため、新規セッションの彗星にも初期201点を使用する。

既定129→201で投影された線分は1,025,810→1,602,202本。各2起動・計6描画の中央値は0.679→1.025秒、実測最大RSSは126.2→142.9 MB。標本を増やした分、全件表示は重くなる。各リビジョンの[ベンチマーク](small-body-render-benchmark.mm)を同じデータで実行した。これは小天体レイヤー単独の計測で、ウィンドウのFPSではない。軌道は初期状態で非表示であり、表示集合を使えば対象を絞れる。[試行別の生値](../../verification/p4/native-orbit-cost.tsv)
