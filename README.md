# Mitaka_plus

Mitaka_plus の天文データを macOS ネイティブのコア・GUI で利用するためのリポジトリ。
`vendor/mitaka` には Mitaka の実装を通常のファイルとして収録している。実行データは `resources/` に収録している。
現在の GUI には恒星・地平表示、星座線・境界・名前、ローカルの NGC/IC・SDSS カタログ表示と検索、太陽系 3D、惑星・月の表面と自転、順逆の時間再生、地表移動、天体間の連続飛行がある。表示状態の保存・復元、PNG/JPEG/BMP 出力、投影ウィンドウ、信頼済みローカル Lua の実行にも対応する。
ローカルの小天体一覧と計算可能な軌道、可視光・赤外線の天の川、画像・動画一覧にも対応する。解釈できない行や参照先が見つからない画像も一覧に保持する。日時は年月日と時差で入力でき、月・年単位の送りと実時間追従を選べる。
恒星名・連星／系外惑星マーク、惑星の本体・名称・軌道・自転軸、座標格子・距離目盛をメニューと Lua で操作できる。月間カレンダーは日曜始まりの 42 セルを使い、日時情報の表示設定とともに JSON の状態保存へ接続している。状態形式は採用する共通実装の単位に従う。

このリポジトリに旧 Mitaka_plus の公式ソースは含まれない。
入手できている公式 Mitaka 1.3.1 のソースから分離したコアと、新しく実装したネイティブ GUI を使用する。
旧 Mitaka_plus の全機能や固有データ形式への対応は未完了。原典と実装・不足の対応は [機能対応表](vendor/mitaka/PLUS_FEATURE_MATRIX.md) を参照。

### 単位4で採用した機能

単位4では、追加衛星の検索・位置表示・日時追従、描画品質 4 項目、主画面の全画面表示/About、信頼したローカル HTML のリンクからの Lua 実行を採用した。JSON v4 に描画品質と衛星の全体表示を保存する。旧開発版 v1 / v2 / v3 は変換せず拒否し、全画面・HTML 信頼・実行状態は保存しない。

衛星は出典・原行・同名定義を保持し、同じ出典・JD で計算した親位置に結び付ける。衛星の物理的な時系と精度期間は未確定。単位4の採用範囲には追加衛星の表面・自転、個体別可視性、探査機 GUI、旧 Lua の全 API は含まれない。

HTML は明示選択したローカル文書のメインページでユーザーが押した `mtkp://` リンクだけを実行元とする。文書内容・ファイル同一性・表示世代を検査し、通常リンクの操作や閉じる操作などで信頼を解除する。ページ JavaScript、Flash、オンライン閲覧・実行は提供しない。Lua helper のファイル・OS 権限は通常のローカル Lua と同じで、サンドボックスではない。

### 単位5で採用した機能

共通実装の単位5を採用し、ラッパーからのビルド・テスト・ローカルデータ検証・公式計算との比較を完了した。採用 SHA と検証結果は下記「採用した共通実装の検証」と `VALIDATION.md` に記録する。

- 小惑星・太陽系外縁天体・彗星は、種別ごとに表示、名称、軌道、表示集合への限定を設定する。表示集合は出典と原行番号で識別し、クリックによる選択・追尾とは分ける。「表示」は種別の全体スイッチであり、オフなら名称と軌道も描かない。軌道線の計算対象は JPL 彗星の TDB evaluator に限る。固定 TDB 区間を初期 129 点で標本化し、1 軌道 2〜4,096 点、要求全体 524,288 点の上限を超える設定は拒否する。36 byte の小惑星・外縁天体は数値 JD による位置評価に対応するが、軌道線は未対応。37 byte など未解明の形式は診断と原行を保持する。
- 追加衛星も、表示、名称、軌道、表示集合への限定を設定する。出典・原ブロック番号で個体を識別し、同名の別行を統合しない。軌道線は表示 JD の親位置と軌道姿勢を固定した瞬間楕円で、将来の運動を積分した軌跡ではない。月や楕円を確定できない行は診断を残す。物理的な時系・精度期間、表面・自転は引き続き未対応。
- 探査機はローカルの定義と PTH を一覧・検索し、確定した位置、本体の点、名称、元の標本に基づく軌跡を太陽系の概観に表示する。選択・中心合わせ・日時追従に対応し、全体表示と点・名称・軌跡を切り替える。元の数値 JD で補間し、範囲外は端点位置に固定する。物理的な時系は未確定のままで、端点固定を運動の外挿とは扱わない。計算できない行も保持し、不正標本を跨ぐ線の補完をしない。PPI はコア読込と評価を保持するが、表示座標の契約が未確定のため描画しない。探査機の形状・姿勢・アニメーションは未対応。
- 星座線・境界・名前の個別表示を、元データの略号による集合として全天図・地平図へ共通適用する。大文字小文字を含む略号を保持し、Ser の 2 図形には同じ設定を適用する。CAB/CDF の星座絵、地平図の天の川、景観はこの単位の対象外。

状態形式は JSON v5 とし、小天体・衛星の種別設定と表示集合、小天体の固定軌道区間・標本数、探査機の表示設定、星座のレイヤーと表示集合を保存する。保存した小天体・衛星の集合には、参照する出典の SHA-256 とバイト数を付ける。復元時は未知・重複 ID、出典の不一致、計算上限などを全体の適用前に検証し、一部だけを復元しない。旧開発版 v1〜v4 の変換は提供せず拒否する。復元後の再生は停止状態とし、一時的な小天体・衛星・探査機のクリック選択、全画面、HTML 信頼、実行状態は保存しない。

Lua は `Asteroids` / `TNObjects` / `Comets` / `Satellites` の表示・名称・軌道・集合限定の 4 真偽値と toggle に対応する。旧英語名を使う `show` / `hide` / `isVisible` の名前解決は未対応で、同名データへの推測による割当てをしない。詳細は共通 GUI 説明・スクリプト説明・機能対応表で確認する。

### 単位6で採用した機能

地平図の天の川、全天図・地平図の CAB 星座絵、恒星名の HIP 選択と明るさ・時間補間、地球の雲・夜景、大気の表示モードと強度、観測地点の user / default・日本語ファイル選択規則を採用した。ローカルの全出典・原行・画像・emmap を保持し、未解決の天体 ID を地球として扱わない。3D 星座絵、景観、地表からの大気などの残る範囲は共通機能対応表に記録する。

状態形式は JSON v6。恒星名の HIP 集合、恒星の明るさ、地球の雲・夜景、大気を含めて全体を検証し、失敗時は正常な状態や進行中の明るさ補間を変更しない。旧開発版 v1〜v5 は変換せず拒否する。再生は停止して復元し、全画面・HTML 信頼・実行状態を保存しない。ラッパーからのビルド・テスト・ローカルデータ検証・公式計算との比較は通過した。

### 単位7で採用した機能

単位7時点では、共通実装の風景、食と影、旧Plusの時間操作を採用した。ローカル画像による風景、食4項目の独立設定、旧Plusの時間step・速度をGUI/Lua/状態保存へ接続した。状態形式は JSON v7 とし、原地点IDと座標を検証して停止状態で復元する。旧開発版 v1〜v6 は変換せず拒否する。地形・銀河は原本の読込・数値モデルまでを含み、3D描画は後続の作業である。ラッパーからのビルド・テスト・ローカルデータ検証・公式比較が成功した。

### 単位8の表示半径

Mitaka の `73d3457969f8bcce88937492b66889a90b22d4bd` から表示半径と、その保存形式・描画に必要な単位8の共通コード（地形・銀河・時間を含む）を採用した。宇宙表示の惑星・太陽と天球図の惑星・太陽／月の4倍率を UI、Lua `Planets:setScale/getScale`、描画と状態保存で共有する。月の模式位置・軌道線にも倍率を適用するが、暦表・着陸・地形・大気・食などの物理計算は変更しない。

状態形式は JSON v9 で、4倍率とモードを保存する。旧開発版 v1〜v8 は変換せず拒否する。宇宙倍率の変更は `KEEP_ORBIT` で行い、カメラ距離補正が未確定の `KEEP_RADIUS` では変更を拒否する。倍率の時間補間 `setScaleTo` は未実装で、惑星 response は暫定値 1 を使用する。旧 Plus との画素一致は未確認。

## 取得とビルド

macOS 13.0 以降、Xcode または Command Line Tools、Git、`make` が必要。
Lua helper は同梱した公式 Lua 5.4.9 のソースを SHA-256 で検証してビルドし、静的にリンクする。ビルド時に別リポジトリやネットワークへの接続は必要ない。

```sh
git clone https://github.com/mocho271828/Mitaka_plus.git
cd Mitaka_plus
make build
make test
```

出力は `vendor/mitaka/native/gui/build/Mitaka Native.app`。

## データと起動

`make run` は既定で `resources/data` を使う。`resources/` には旧 Plus のデータと関連ファイルのコピーを収録する。表面画像や探査機の定義も同じ親ディレクトリから読み込み、データは読み取り専用で参照する。

```sh
make run
```

別のデータを使う場合は、`hip.dat` と `cf96.dat` が直下にある `data` ディレクトリの絶対パスを指定する。表面画像や探査機データは指定した `data` と同じ親ディレクトリにある `textures`、`spacecraft` を参照する。

```sh
export DATA_ROOT='/absolute/path/to/mitaka_plus/data'
make run
```

起動後にデータを選択する場合は、ビルド後のアプリを直接開く。

```sh
open -n 'vendor/mitaka/native/gui/build/Mitaka Native.app'
```

操作方法と表示上の制約は [GUI の説明](vendor/mitaka/native/gui/README.md) を参照。

## 検証

```sh
make test
make data-test
make reference-test
make smoke
```

`make test` はデータなしでコア・GUI・再生・出力・Lua コントローラのテストを実行する。
`make data-test` は同梱データ、または `DATA_ROOT` に指定されたデータを読み取り専用で検証する。
`make reference-test` は公式 1.3.1 原本との惑星位置・自転・月・大気・食計算の比較を実行する。
`make smoke` は実アプリで描画・表示状態復元・画像符号化・再生・飛行・Lua 接続を検証する。`data-test`・`reference-test`・`smoke` には既定の同梱データを使用できる。
Plus の Makefile は `DATA_ROOT` を常に `data` ディレクトリとして受け取り、コアのデータテストに渡すときだけ親ディレクトリへ変換する。

## 保存範囲と利用条件

このリポジトリには実行に必要なソース・設定と、Plus の天文データ・画像を `resources/` に収録する。旧アプリと Wine 環境の原本は保持し、ビルド生成物や認証情報は登録しない。データには独自追加が含まれるため、共有する際は公開範囲と各データの利用条件を確認する。

公式 Mitaka 1.3.1 の由来と許諾表示は同梱した [ソース入手先の記録](vendor/mitaka/SOURCE_AVAILABILITY.md) と [第三者コードの表記](vendor/mitaka/native/gui/THIRD_PARTY_NOTICES.txt) を参照。Lua は [専用の許諾表示](vendor/mitaka/native/gui/LUA_LICENSE.txt) をアプリへ同梱する。

Lua はユーザーが信頼して明示選択したローカルファイルを実行する。ファイル・OS 操作はユーザー権限で行われ、サンドボックスではない。対応 API と旧 Lua との差は [スクリプト説明](vendor/mitaka/native/gui/SCRIPTING.md) を参照。
コードの許諾から旧 Mitaka_plus 本体や天文データ・画像の改変・再配布条件を推定しない。
このリポジトリ全体に新たな一律のライセンスを付与しない。

実装時の判定入口は [IMPLEMENTATION_POLICY.md](IMPLEMENTATION_POLICY.md)。
