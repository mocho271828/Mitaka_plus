# 旧 Plus 実画面での測定方法と結果

Windows 版の通常ウィンドウに表示された星図を PR #8 の地平図と比較した。方位は北 0°・東 90°、高度は水平 0°。旧版には対象が表示されない例と、対象は表示されても注視命令がその位置を向かない例がある。このためカメラの保存値と表示画素を別々に測った。

## 実行ファイルと入力

[作者配布の Mitaka Plus 1.5.4](http://orihalcon.jp/mitakaplus/downcnt.cgi/mitakaPlus_154.zip) の `mitakaPlus.exe` は SHA-256 `48961f09019e0e43f23f2537752978dc16c563c807f5b048ba5b0448c0d2b457` で、既存の旧環境の記録と一致した。配布 README が指定する [通常版 1.2.0](https://4d2u.nao.ac.jp/html/program/mitaka/software/mitaka_120.zip) の不足ファイルを補い、天文データは PR #8 と同じ実体をコピーした。`mp.dat` は `892dc28ad165126dfed1c94bd3934870986da5eda7f3b155d33ac67e43dd940c`、`Voyager_I.pth` は `b31e441a8508117d52d24cd2cd49904e88fc5068a5a5ffaf0da22f9b08e57ac1`。外部配布物・Wine・撮影画像はローカル検証用で、Git には収録していない。

Apple Silicon Mac 上の [Boxedwine 26R1](https://github.com/danoon2/Boxedwine/releases/tag/26R1.0) と Wine 11.0 で起動し、主測定には OSMesa を使った。Windows ウィンドウのタイトルは `Mitaka Plus Version 1.5.4 (Oct 13 2010)`。画面内のバージョン情報を有効にすると `Version 1.4.0` と出る。同じ executable に両方の文字列があり、PE アドレス `0x470cb5` と `0x47ca86` から始まる命令列は `1.4.0` と `Version %s` を整形関数に渡す。比較時はこの重なる画面内表示を消した。

## 条件と判定

`Places:addPlace` で東経・緯度を渡し、`Camera.target`、`Camera:forceMode(mtk.PLANETARIUM)`、`Time.realtime=false`、同一の数値 `Time.JD` を設定した。観測地点は三鷹 (35.675° N, 139.540° E)、グリニッジ (51.477° N, 0°)、追加のはやぶさ最終標本は南太平洋 (37° S, 154° W)。旧版の時計は固定時差表示で、JD の小数部が二進数で正確に表せない 13:00 UTC のケースでは、旧版の整数秒表示と状態ファイルは 12:59:59 UTC 相当になった。プログラムに渡した JD を表の比較キーとした。

データ読み込み完了後、通常ウィンドウで `Camera:look` を実行して `State:storeAsInit` のカメラ値を読んだ。観測日時と視野を保ち、対象の名称・表示集合を有効にして種別スイッチだけを切り替えた。旧版注視の視野と、native で求めた方位・高度へ数値で向けた視野の両方を測定した。各操作を旧スクリプトエディタの `waitTime` で区切り、対象プロセスに属する表示中のウィンドウ番号を確認して撮影した。画像 1920 × 1504 px の左上から (40, 260) を原点とする星図 1600 × 1060 px について、RGB のいずれかが異なる座標を数えた。テーブルの `phase` はローカル `local/verification/p3-oldplus/shipping/<phase>.png` と同名の保存状態 `.lua` に対応する。

- [19 条件の表示差分と画像ハッシュ](p1-2-legacy-window.tsv)。セレス、ハレー彗星、Voyager I、はやぶさ、ヘール・ボップ彗星の 17 条件は、両視野とも対象スイッチの切替による変化が 0 px。セレスと Voyager I はグリニッジで名前による選択も行い、旧版の情報パネルで対象を識別した。近接時のはやぶさは軌道表の最終標本、地表観測地点まで約 2,347 km の例を含む。これらには旧画像から位置を決められる独立のマーカーを確認できず、表示位置の角度差を報告できない。数値のある `look_to_native_separation_deg` は旧版カメラと native 天体方向の差である。正の対照では、同じ星図の恒星切替で 39,873 px、太陽を含む惑星切替で 4,576 px が変化した。
- 旧版のセレス名は `Asteroid.Ceres` と `Asteroid.1`、Voyager I は `Spacecraft.VoyagerI` で期待する対象の高度を得た。複数形 `Asteroids.Ceres`、`Asteroid.#1`、空白入り `Spacecraft.Voyager I` は太陽への注視と同じ値を返した。旧版で保存した `Camera.azimuth` は画面の東正表示と符号が逆で、注視方位が 90° や 270° に寄る例もあった。[高度・地球姿勢の独立計算](p1-2-legacy-attitude.md)を参照。
- ホームズ彗星は 2007-10-27 の両地点で、45° 視野の表示切替によって `Holmes` の文字形状が 1,148〜1,220 px 現れた。飛び先のカメラを天体画素と見なさず、次の方法で実表示を測った。

## ホームズ彗星の方位・高度

10 月 27 日と 28 日の 13:00 UTC に、両地点で `Comet.Holmes` を同じ設定で撮影した。基準カメラは native の対象方向。画角 4° と 16° ごとに基準、方位を +0.25°、高度を +0.25° にした 3 姿勢で表示と非表示を切り替え、画角 8° の基準視野を独立検証用に加えた。4° の 4 条件すべてで、ラベルだけを消すと対象種別オフとの星図差分は 0 px だった。

各ペアの差分の最大 RGB 振幅の平方根を用い、4° の基準ラベルと同じ字形を相互相関で位置合わせした。相関の頂点を両隣から二次補間した。`P(f)` を画角 `f` の基準フレームでの字形位置とし、既知の 2 軸の視点変更から `J(f)`（視点変更 1° あたりの画素変位、2 × 2 行列）を求めた。天体と基準カメラの角度差 `d` は `(J(16) − J(4)) d = P(4) − P(16)` から算出した。同じ字形の移動だけを使うため、文字の余白を天体位置に加算しない。結果の [角度・別方式との照合](p1-2-holmes-position.tsv) と、計算を追試できる [28 件の画素位置・ハッシュ](p1-2-holmes-label-pixels.tsv) を記録した。

旧表示と PR #8 の天体方向の角距離は 0.1463〜0.1485°。別日の姿勢で再現し、最低相関係数は 0.858。4° と 16° の変位を焦点距離（画角半分の余接）で補間した 8° 位置と実測との差は最大 0.39 px。差分を単純に二値化して同じ字形登録を行った場合、主結果との各軸差は最大 0.0034° だった。全桁がこの精度で保証されるわけではない。通常の Windows ネイティブ実機での繰り返しや、他の全小天体・探査機での検証はしていない。
