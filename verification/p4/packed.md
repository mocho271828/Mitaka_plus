# 旧 Plus 1.5.4 で使われた小天体カタログ

Windows 版 Mitaka Plus 1.5.4 は、検証した3回の起動と小惑星・太陽系外縁天体の表示操作では、36 byte の `mp.dat`・`TNO.dat` を要求した。両ファイルを置かず、37 byte の `mp2.dat`・`TNO2.dat` だけを置いても、37 byte 版を開く試行は0件だった。比較したのは作者配布 build101013（実行ファイル SHA-256 `48961f09019e0e43f23f2537752978dc16c563c807f5b048ba5b0448c0d2b457`）を、Apple M4 の Boxedwine 26R1 / Wine 11.0 / OSMesa で実行したときの動作である。[旧実行環境の由来](../p1-2-legacy-window.md)

## 原ファイルと読み込み

作者の1.5.4差分ZIPには、この4ファイルはいずれも入っていない。前提の通常版1.2.0 ZIPには `mp.dat` と `TNO.dat` があり、同梱実データと全バイトが一致する。PR #8 の37 byte全行で番号直後の1 byteを除き、対応する36 byte全行と元データを照合した。小惑星は7,317件すべて、外縁天体は1,193件のうち1,134件が一致し、59件には一致する36 byte行がなかった。追加byteの値は小惑星で0が7,316件・1が1件、外縁天体で0が1,190件・2が3件だった。[出典・サイズ・ハッシュと全件照合](packed-inputs.tsv)

旧版アプリとWine環境の作業用コピーで、4ファイル全部、36 byteの2ファイルのみ、37 byteの2ファイルのみの3条件を順に起動した。他のカタログ・個別天体定義・画像は同じものを使った。Wine の `WINEDEBUG=+file` で対象の `CreateFileW` の戻り値、同一スレッド・ハンドルの `ReadFile` と `NtReadFile` の成功バイト数を追跡した。先の2条件では小惑星263,412 bytes、外縁天体40,824 bytesを全量読み取った。後者2ファイルだけを置いた条件では旧名のオープンが各1回失敗した。3条件・いずれの37 byteファイルでも読み取り用オープンは0回だった。[各条件でのオープン・実読込量](packed-opens.tsv)

## 旧版の表示操作

宇宙モードで太陽を対象、JD 2453695.0、画角45°、小惑星・外縁天体ともに「選択のみ」、名称、軌道線をオフとした。太陽から12 AUで小惑星を表示し、100 AUで外縁天体を表示・非表示にした。各旧版ウィンドウから1920×1504 pxの実画像を取得。37 byteのみの一部画像で、左上にQtのFileメニューが重なったため、全9枚とも同じ完全可視の地図領域（左上 x=440, y=440、1120×800物理px）を比較した。操作時に保存した状態ファイルは描画より先に書かれるため、画像の一致は画面から求めた。

| 896,000画素のうち、4ファイルすべてを置いたときとのRGB差 | 小惑星を表示 | 外縁天体を表示 | 両方を非表示 |
| --- | ---: | ---: | ---: |
| 36 byteのみ | 0 | 0 | 0 |
| 37 byteのみ | 1,658 | 48 | 0 |

この実行版の通常のローダー・操作では、37 byteを追加しても小天体地図に変化がなく、36 byte欠落時の代替にもならなかった。別製品 Mitaka++ での分岐や、他バージョン・追加設定・原フラグ0/1/2の天文学的な意味はこの比較の対象外である。[画面ハッシュと条件](packed-legacy-windows.tsv)・[Mitaka++ の既存監査](../../investigation/native-plus/minor-planet-37-byte-audit.md)

## PR #8 の表示

太陽系画面の実データを読み込み、アプリの「小惑星・太陽系外縁天体・彗星」ウィンドウで出典と原行番号を検索し、表示集合を該当1行に切り替えた。一覧と完成地図を ScreenCaptureKit で自プロセスのウィンドウごとに撮影した。修正前は37 byte行でフラグが未解釈という診断を表示したが、原値の数値を読めなかった。詳細表示へ形式・値・意味未確定を明記した。

- セレスの `mp.dat #0`、エリスの `TNO.dat #1097` は位置を返し、同じ観測JDの太陽系画面に原フラグ表示の比較に使った129標本で各128線分の軌道が描かれた。
- `mp2.dat #0`（原番号1）、`mp2.dat #1`（原番号2）、`TNO2.dat #124`（原番号136199）に原フラグ 1・0・2 がそれぞれ表示された。3行とも位置を返さず、軌道線分は0本だった。37 byte の小惑星2行を切り替えた地図全2,039,824画素のRGBは一致した。
- 同一番号の36から37への切替で、地図のRGBはセレスで5,666画素、エリスで4,933画素が変化した。原値表示の修正前後では5例すべて、同じ対象の地図全画素が一致した。画面の計数・ハッシュと詳細表示の差は[ネイティブ30枚の撮影記録](packed-native-windows.tsv)を参照。

近日点始点・既定201標本の統合版でも、同じ5行を再選択して一覧と地図の10枚を撮影した。36 byteの2行は各200線分、37 byteの3行は位置なし・線分0本で、原フラグの表示は1・0・2だった。37 byteの各地図は明示129標本との比較で2,039,824画素全RGBが一致した。

原画像・状態ファイル・Wine読込ログは検証 Mac の `local/verification/p4-packed/`、ネイティブ画像は `native-before/` ・`native-ok/`・`native-201/` に保存した。
