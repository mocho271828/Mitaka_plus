# 統合版の姿勢変更を実画面で検証

2026-11-12、ネイティブ版 `18b46fe` と計測表の `after` に対応する版を Apple M4・macOS 26.6.2 で実行した。同梱データと一致する575ファイル、JD 2451545.0、時計停止。製品の AppController・ビュー・Lua helper を使い、WindowServer の PID とウィンドウ番号を照合した AppKit ウィンドウを ScreenCaptureKit で撮影した。測定専用の Retina ディスプレイに画面を置き、WindowServer の合成後に取得した。各画像と入力・取得条件は [ネイティブのフレーム表](native-frames.tsv) にある。

宇宙は Lua `Camera.target='Planet.Earth'` で対象を地球に指定し、`Camera.zoom=1*mtk.UNIT_AU` と `Camera:setEuler(0,0,0)` を設定した。地心位置は (−0.177135095821834, 0.967241685472967, −0.000004092994695) AU。旧版の設定尺度と物理距離を区別し、旧版の zoom 1 AU が当該設定で視点距離約0.30865 AU に相当する対照も撮影した。

- 比較対象（`18b46fe`）での即時 `Camera:setEuler(30,20,35)` の Lua `getOrient` は (+0.0833221455591, −0.293527817054, +0.328910100787, +0.893709676727)。現行の変換では (+0.0833221455591, +0.293527817054, −0.328910100787, +0.893709676727) で、旧版から直接読み戻した値の表示精度内に一致する。
- 同じ終点に、即時 `setEuler` と4秒の `setEulerTo` の双方で到達し、それぞれの停止画像はウィンドウ全5,288,960画素の RGB が一致した。同様に `setOrient` と4秒の `setOrientTo` でも一致した。[即時と停止後の画素比較](native-endpoints.tsv)
- 三鷹（東経139.54°・北緯35.675°）の地平図は初期方位0°、高度22.5°、ロール0°、FOV45°。方位70°・高度12°の即時・4秒変更、Euler (30,20,35) の即時・4秒変更を実行した。Euler終点で表示用の地平方位は133.18144°、高度−5.64893°、画面ロール−21.98370°。Euler即時と補間停止後はウィンドウ全画素が一致。方位・高度の即時と停止後は姿勢・quaternionが一致し、画素差3,442は状態表示の矩形（x=208–499、y=1962–1981）に限られた。
- 独立した Lua 実行で、宇宙Euler、地平方位・高度、地上Euler、宇宙quaternionの4秒補間の途中に `Camera:getEuler()` と `Camera:getOrient()` を直接読み戻した。Lua helper との通信・撮影に約0.2〜0.3秒かかるため、値の前後にホスト側snapshotの取得時刻を記録した。[移動中のLua実読値と前後の姿勢](native-lua-readback.tsv)

# タイマー配信の遅延と再指定

画面描画などによりメインスレッドのタイマー配信が遅れた条件を独立させた。地球・1 AU・Euler (0,0,0) から Lua `Camera:setEulerTo(90,0,0,10,false)` を開始した後、メインスレッドを意図的に5秒停止。その間はタイマー通知を一度も処理せず、経過後、Lua helper が通常使用する同じホスト action に相対Euler (0,0,0) を指定して直後の画面を撮影した。

タイマー通知時の姿勢を使う方式では、停止前に最後に更新された0.609277°の姿勢から再指定され、画面も変化しなかった。経過時刻を使う方式では指定直前に経過時間で姿勢を更新し、46.924169°から再指定する。実際に `Camera:getEuler/getOrient` を別Lua実行で読み戻した値も同じだった。全条件の数値と画像 SHA-256 は [再指定のフレーム表](native-retarget.tsv) にある。この条件は意図的なスレッド停止を含み、通常利用の応答速度の測定ではない。
