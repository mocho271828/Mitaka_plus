# Gate: ビルド・検証・変更管理

## 目的

共通実装の参照先とデータの渡し方を、再現可能なビルドと検証で確認する。

## 判定条件

- [ ] `make build` と `make test` が成功する。
- [ ] データ参照や submodule の採用コミットを変更した場合、既存データを指定した `make data-test` と `make reference-test` が成功する。
- [ ] `DATA_ROOT` は絶対パスの `data` ディレクトリとして受け取り、コアのデータテストにはその親ディレクトリを渡す。
- [ ] submodule 未取得や `DATA_ROOT` 不足の場合は、手順を示すエラーで停止する。
- [ ] 作業完了時に `git status`、変更ファイル、差分量を確認し、300 行以上の変更では原則 commit する。
- [ ] commit 前に `/simplifier-lai` skill の利用可否と依存関係を確認し、利用できない場合は報告する。
- [ ] gate 検証用コピーに判定を記録し、実施したテストと未実施の確認を作業報告へ残す。
- [ ] 追加衛星・描画品質・全画面・HTML を採用する場合、共通側の対応試験と採用 SHA を特定する。HTML helper の構成、実 OS 通知、実機・複数画面など未確認の範囲を成功扱いしない。
- [ ] 単位6の採用時は、JSON v6 の正常復元・不正 ID/出典不一致/上限超過による全体拒否、小天体・衛星の表示集合、PTH 探査機、全天図・地平図の星座集合・星座絵・天の川、恒星名選択・明るさ、雲・夜景・大気について共通側の試験を特定し、ラッパーからの検証結果と区別して記録する。
- [ ] 採用準備中の機能には未確定の commit・gitlink・検証結果があることを明記し、採用前の機能を現在固定された submodule の検証済み機能と説明しない。`VALIDATION.md` と gate の判定は実際の採用 SHA・実施結果だけを記録する。

## 不合格条件

- [ ] 失敗した検証を成功として報告する。
- [ ] submodule 内の未 commit の変更を、Plus の gitlink 更新だけで保存したと扱う。
