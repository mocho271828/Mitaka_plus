# 大気散乱と emmap の出典・数値契約

N12 は[公式 Mitaka 1.3.1](../sources/README.md) の scalar 単一散乱・多重散乱を移植し、ローカル Plus と通常版の `data/emmap.dat` を読み取り専用で利用する。Plus の旧実行ファイルと画素単位で同じ描画になることや、観測に対する物理精度は主張しない。座標系から表示色までの計算と適用範囲は [大気描画](../gui/ATMOSPHERE_RENDERING.md) に記録する。

## 根拠と保持する入力

| 公式ファイル | 用途 | SHA-256 |
| --- | --- | --- |
| `Mitaka/mtk_atmosphere.cpp` | scalar 計算、map loader、描画 RGB | `e9cef8417960ea795b6d40f49c9778a130d508a65de6a8635f7709f783c08e89` |
| `Mitaka/mtk_approx_func.h` | `exp_d` | `025b8e8904959c2e0eece00f73c20a079fcc9a3d7220b507015f832ede23c298` |
| `Mitaka/mtk_planets.cpp` | Earth / Mars の通常描画パラメータ | `a8a1343409790b23fa69dcc852a5a36ca111e3fc7f78861ef9344690fd23bb41` |

原版由来の計算ファイルには許諾表示を保持する。新しい依存は追加せず、既存の `Vec3`、`CatalogLoadLimits`、`CatalogError` と C++17 標準ライブラリを利用する。

ローカル Plus と通常版の emmap は双方 983,088 bytes、SHA-256 は `cec4e25b01a793bdd131b896a3404ff40132bc31d6e94fe3c04ed9a3a3fc1013`。ヘッダーは `RN=20, ThN=4096, R1=6378000, R2=6442000, H=8000, N0=2.5469e25, ThMax=1.884955644607544`。原本ファイルを編集・正規化・上書きしない。

`AtmosphereEmissionSource` はパス、ファイルサイズ、読めた原 bytes、読込完了フラグ、診断を保持する。欠損・破損・上限超過は `map=nullopt` と診断で表す。不正ファイルも上限内なら原 bytes を残し、正常な黒い map に置換しない。ファイルのサイズを allocation 前に調べ、読込中の短縮・追加も失敗として扱う。byte 上限超過時はファイル全体を allocation しない。

## emmap の検証

公式 loader の 541–569 行から、little endian の 48 byte ヘッダー（signed int32 の次元二つ、double 五つ）に続く、半径行優先の RGB float 三成分を採用する。半径は `R1+(R2-R1)*i/(RN-1)`。原 loader にない防御は native の入力境界として追加する。

- 次元は各 2 以上、signed int32 範囲。次元積を乗算前に `max_records` と比較し、全サイズが `48 + RN*ThN*12` と完全一致することを要求する。
- `0 < R1 < R2`、`H > 0`、`N0 >= 0`、`0 < ThMax <= π`、全値が有限。二乗半径・角度刻みが扱える数値範囲にあり、生成した半径が厳密に増加することを検査する。
- 全 RGB ノードが有限かつ非負。負値、NaN、無限大、切断、余剰 bytes は拒否する。
- 検証済み map の内部は共有された不変データとし、画素ごとに全ノードを再検査しない。

## 計算の契約

入力は惑星中心から視点までの m 単位ベクトル、視点から画素への単位方向、惑星から太陽への単位方向。同じ直交基底を使う。方向の norm 許容差は `2e-6`、視点は対象の地表以上とする。不正入力は `invalid_argument`、扱えない数値範囲は `out_of_range`。大気に前方交差しない場合の RGB=0 は正常結果。

単一散乱は既定 14 標本、公開 API は 2–4096 標本を受け付ける。公式 264–499 行の演算順と float の丸め位置を保持する。

- 波長 700 / 546.1 / 435.8 nm は原 float 値から double 係数を計算する。
- `exp_d(x)` は `(1+.2507213x+.0292732x²+.0038278x³)^-4`。`std::exp` に置換しない。
- 視線・太陽方向の光学深度は double、各 RGB 加算は float。太陽側の標本数 `samples-i+1`、積分の分母 `samples` と最後の幅の分母 `samples-1` を区別する。
- `R1 *= .9999` は地表クリップ・影の円柱・密度に適用する。原コメントは `//*****` のみで、物理的理由は未確定。
- 昼の二つの区間、位相係数内の `3.141592654`、最後の入射強度を保持する。

多重散乱は公式 587–747 行の、500 要素の acos 表の floor 参照、角度の float 補間、内向きから外向きの殻積分、加算前後の半光学深度、float RGB 蓄積を保持する。map 自身の半径・密度を使い、単一散乱の設定へ書き換えない。多重散乱だけの結果には入射強度を含めない。

`compose_atmosphere_display` は float の `single + I0*multiple` と `alpha=min(1,4*max(RGB))`。RGB は加算合成用であり、この alpha は透過率ではない。再乗算しない。

## native の境界追加

原描画側に依存していた前方交差条件を公開関数で検査する。地表ちょうどから内向きの光線は厳密な黒とする。原関数は桁落ちによりこの境界で約 `1e-13` 以下の負値を生成し得るため、原版との通常の数値照合から分けて回帰する。

`AtmosphereRay.maximum_distance_m` は native の不透明物体までの積分終端。未指定なら原版の全光路、指定時は有限かつ非負を要求する。単一散乱では照らされた区間を切り、多重散乱では元の殻 sample の位置・角度・密度を保ったまま末尾の区間長を短縮する。任意の遮蔽終端は原版 scalar API にない拡張であり、全光路の原版照合とは別に検証する。

## 局所検証

2026-10-29、通常 arm64、ASan/UBSan arm64、x86_64 の各構成で strict C++17 ビルドと全実行が exit 0。製品側に警告抑制を追加していない。

| 試験 | 各構成の結果 |
| --- | --- |
| `test_atmosphere` | 733 checks PASS。正常 map、原 bytes、欠損、破損、サイズ・次元上限、異常数値、昼夜・地表・前方交差、終端による切断を検証 |
| 公式抽出参照 + Plus emmap | 単一 12,606 成分すべて完全一致。多重 1,584 成分は下記の範囲内。64 地表内向き ray は native が厳密 0 |
| 公式抽出参照 + 通常版 emmap | 同上。全ヘッダー・全半径・全 RGB ノードも原 loader と完全一致 |
| GUI の純描画回帰 | 各 4,259 checks PASS。[描画の検証範囲](../gui/ATMOSPHERE_RENDERING.md#検証)を参照 |

arm64 の通常 / SAN の多重散乱は 1,584 成分中 1,385 成分が完全一致、最大絶対差 `3.0517578125e-05`、最大相対差 `1.63027751399e-07`。x86_64 は 1,584 成分すべて完全一致。上限は `8 * float epsilon * max(abs(actual),abs(expected))` で、ゼロを通す固定の絶対許容差は使わない。float 演算の最下位差を扱う比較であり、物理精度を表す数値ではない。

移植時の比較では、公式版の scalar 関数と `vector3.h`・`mtk_approx_func.h` を使い、SSE 経路を無効にした。地表から内向きの光線は上記の境界条件で個別に検証した。

## 今回の対象外

地上 planetarium の 22 標本、外層 `R1+20H`、日食、gamma 補正、`r0/zoom` は別経路。大気による背景・恒星の減衰、SSE 最適化、旧 GL mesh と同じ分割・間引きは未移植。この core と物理球への加算描画ができたことをもって、Mitaka_plus の全機能の実装完了とはしない。
